# Diagnosed failures and corrections

1. First real-ROM capture looped at PC 0038 (RST 38), with zero I/O writes. The CPU was real TV80, but the initial bus mux returned ff after RD rose, before CE sampled dinst/di_reg. Holding the registered read response through T2/T3 fixes the first divergence. `tests/tb_cpu.sv` reproduces opcode, RAM, I/O and NMI/RETN operation at a sparse CE. No golden data was changed.
2. Four-state ADPCM vector observed -1 instead of the documented -2 reset rest level. The upstream expression compared signed sound to unsigned `12'd0`, causing every negative value to enter the shift/fade branch. `patches/jt5205_adpcm.v.patch` makes both comparison literals signed. Original source remains intact; the selected derived file passes the independent 256-nibble saturation/pipeline vector.
3. Pinned platform failed strict Verilator elaboration because hps_io PS/2 declarations were scoped inside a generate block but referenced from outside, and HQ2x Blend's procedural Result output was a wire. Minimal recorded patches move those declarations to module scope and declare Result as reg. No HPS/video algorithms were replaced.
4. Initial Windows C++ runner compilation required the installed Verilator's generated child-class API, explicit VlUnpacked indexing and sc_time_stamp definition. These are host harness fixes only.
5. Icarus 14 rejected the upstream arcade_video.v forward declaration usage in SystemVerilog mode, while Verilog-2005 mode rejected its local declarations. The rotation executable therefore uses Verilator and explicitly reports two-state initialization. Board and sound four-state tests still use Icarus. No platform block was stubbed to pass the check.

6. TV80 unconditional RET used five T states for the fetch, yielding 11 rather than 10 T states. The Mode 0 microcode now uses four. A standalone CALL/RET timing program fails on the original and passes on the derived file.
7. TV80 refresh logic was optional and disabled, so the game read zero from LD A,R. TV80_REFRESH is now enabled everywhere. The LD A,R flag path incorrectly used I; the derived core uses R and supplies X/Y flags. Prefix increments, seven-bit wrap and HALT refresh are tested.
8. TV80 NMI took 15 instead of 11 T states: two unnecessary acknowledge waits and two four-T stack cycles. Mode 0 excludes NMI from maskable-interrupt wait insertion and uses three-T stack cycles. The original fails the NMI timing fixture; the derived CPU passes entry, pushed PC, HALT wake and RETN.
9. Port 05 read ff while MAME noprw reads zero. The game complements this value and writes it back. An explicit zero response now matches every port-05 read/write in the corrected 300-frame gameplay run.
10. Platform video_mixer RGB wires were declared inside generate branches and used outside, producing implicit undriven wires. Module-scope declarations fix the real video path. Disabled PS/2 host data, arcade freeze and HQ mono inputs are explicitly tied to their intended values. Real platform video and HPS tests now exercise these paths.
11. MAME raw screen:pixels captures were the back buffer after a frame swap. Displayed PNG snapshots agree with independent rendering of same-frame MAME RAM. Comparisons now use displayed PNG, retain back-buffer diagnostics and keep earlier failing reports. Remaining water-animation differences are still failures; no golden image was altered to match the DUT.
12. MAME re-invoked the autoboot Lua script after soft reset. A global installation guard now preserves one callback and a continuous frame counter. A fresh completion.json is required, so stale captures cannot establish a passing reference run.

All I/O, including no-op port 05, is now compared. Functional-I/O retains its historical narrower definition only for continuity. Digital audio donor pipeline/reset behaviour and provisional raster/CPU phase remain explicitly documented rather than hidden by changed expected hashes.

13. The first real Quartus synthesis failed Error 15836: direct CLK_50M reached clock-select input 3, which requires a PLL output. The recorded sys_top patch places clk_vid on input 1 (clock-pin capable), retains HDMI PLL on input 2, and changes selection 3/2 to 1/2. Clock rates and game RTL are unchanged. Rerun Analysis & Synthesis passes with zero errors; fitting/timing are separate stages. Original failing log and input hashes are preserved as quartus_map_clock_input_before.*.

14. All C++ Verilator harnesses (`drmicro_sim.exe`, `platform_hps_test.exe`, `platform_video_test.exe`, `rotation_test.exe`) are built by the project-pinned MSYS2 UCRT64 GCC 16.1.0 but this Windows shell resolves `libgcc_s_seh-1.dll`/`libwinpthread-1.dll`/`libstdc++-6.dll` from a different MSYS2 environment (`/mingw64/bin`) that happens to precede UCRT64 on `PATH`. The mismatched runtime DLLs are ABI-incompatible: `drmicro_sim.exe` failed to start at all (`STATUS_ENTRYPOINT_NOT_FOUND`, 0xC0000139) while `platform_hps_test.exe` loaded but crashed later. This silently corrupted one full `test_all` run: `run_smoke` failed but `compare` then passed by diffing a stale prior-run capture against a freshly regenerated MAME reference, producing a false PASS. `tools/dev.py` now links all four harnesses with `-static`, so they carry their own runtime and are immune to `PATH` order in the invoking shell. Verified by re-running every harness from a shell with the conflicting `/mingw64/bin` ahead on `PATH`: all four now start and pass. No RTL or assertion was touched.

15. `test_platform_hps` segfaulted (SIGSEGV, exit 3221225477) with zero output on Windows/MSYS2 UCRT64 GCC 16.1.0, on an otherwise unchanged source tree. Isolated by compiling `sim/platform_hps.cpp` and the Verilator-generated `platform_hps_top` model at independent optimization levels: the crash tracks only the harness translation unit's optimization level (`-O0` passes, `-O1`/`-O2` crash), never the RTL model's (`-O0` or `-O2` RTL both pass when linked against an `-O0` harness). `#pragma GCC optimize` bisection localized it to the post-resume fetch-counting loop; `-O2 -fno-inline` alone (no other flag) fixes it. This is a GCC 16.1 inliner defect in this host toolchain, not an RTL or protocol defect: the RTL model is unchanged and passes at every optimization level tested. `tools/dev.py` now compiles this one harness with `-fno-inline`; no other build target is affected. No assertion was weakened; the harness's actual checks (malformed/full download, DIP isolation, both gamepads, PS/2 make/break, aspect/status, OSD reset, CPU resume) all execute and pass under the fix.

16. Root-caused the frame-240 `play` strict mismatch (24 differing RGB pixels, video-RAM addresses 0xE0E1/0xE181). A fresh `DRMICRO_FRAME_STATE` PC/R trace at the NMI boundary (x=316,y=239) shows the DUT and MAME agree on PC and R exactly at frame 240 (pc=194,r=91 both sides) and differ by only one PC count, with R still exact, at two nearby frames (236, 242) — CPU/interrupt timing is cycle-accurate here; there is no execution drift. A cycle-stamped write trace shows the game writes both disputed video-RAM tiles at y=253 and y=254 (cycle ~200,273,909 / ~200,278,011), deep inside vblank (y=240..255,0..15) and about 43,000 cycles (13 raster lines) after the DUT's own `frame_240.ram`/`.ppm` dump point (x=0,y=240, cycle ~200,230,502, from the matching NMI-boundary sample). By y=255/0/8 of the following pass the write is already committed in RAM. MAME's `frame_240` snapshot already shows the new tile values. This means the two harnesses define "frame 240 complete" at different points within the same 32-line vblank: the DUT dumps at vblank *start*, MAME's `register_frame_done` callback evidently fires later (nearer vblank *end*), so a write landing in between appears in one capture but not the other. The DUT's live-rendered active picture for frame 240 (rows 16-239, drawn before the write, in the pass preceding y=240) is unaffected either way — a real CRT would show exactly what the DUT shows. Frame 300 (60 frames later, after both sides have long converged) is exact RGB/video-RAM, confirming this is a one-off capture-instant artifact tied to this specific animation write, not a persistent drift. Classified **KNOWN** (not INFERRED): the PC/R trace and write-cycle trace are direct evidence, not modelled assumption. No RTL or comparison-threshold was changed to force a pass; `reports/verification_summary.json` correctly stays FAIL until the harness's snapshot instant is moved to align with MAME's (tracked in `docs/plan.md`), or a hardware-backed exception is recorded.
